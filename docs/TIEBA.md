# 百度贴吧实际测试

日期：2026-11-03（Asia/Shanghai）。本测试使用真实官方贴吧，不以受控测试应用代替贴吧。机器、网络和广告填充会影响结果，以下结论仅覆盖已执行的场景。

## 官方应用与环境

- 官方入口：https://c.tieba.baidu.com/c/s/download/pc?src=webtbGF
- 包名 `com.baidu.tieba`，版本 `22.13.1.1`，versionCode `369950981`，ARM64。
- APK SHA256：`98545203220765504f8f23b55dd32fb49c1c5cef06ae80f0e83f533687a9106e`。
- 下载经过 Baidu 的 `downpack.baidu.com`、`downapp.baidu.com`；APK v2 签名验证通过，证书主体标识 Baidu Tieba/Baidu，证书 SHA256：`81e69ceb1b2566d435ecd5173b9ad0370c8e7b01760ac5c7e6b559266a221193`。
- AOSP Android 15 / API35 ARM64，1080×2400，模拟蜂窝网络；宿主网络的 DNS A 记录使用 `198.18.0.0/16` 合成地址。
- 净屏通过 Android per-app VPN 仅处理贴吧，系统无障碍开关保持关闭。新版生产 APK 无无障碍服务声明。

首次启动阅读并同意官方协议，拒绝通知，不登录账号。不向贴吧输入电话、密码或验证信息。启动页显示登录入口；其 Manifest 声明的公开 VIEW 路由 `com.baidu.tieba://unidispatch/frs?kw=xiaomi` 可打开“小米吧”，用于测试公开内容。没有修改贴吧 APK、注入登录态或使用私有账号数据。

## 已观察到的结果

| 项目 | 结果 |
| --- | --- |
| 净屏停止时打开公开“小米吧” | 普通帖子和图片可以加载，滚动检查 6 个页面位置 |
| 公开吧页基线外发 DNS | 观察到 59 次命中内置广告/跟踪列表的 UDP DNS 查询 |
| 开启“仅拦截贴吧”，清理贴吧测试数据后重新启动并进入吧页 | 净屏计数从 16 增至 100，即 84 次请求被阻断 |
| 开启过滤后的外部抓包 | 未见命中内置列表的 UDP DNS 查询外发；被拒请求在本地处理，不进入外部抓包 |
| 过滤后的普通内容 | 帖子、图片和连续滚动仍能加载 |
| 无障碍开关 | 0，未启用；不自动点击广告或“跳过” |
| 明确标注的广告卡片 | 基线和过滤样本均未采集到，视觉去除效果未定 |
| 真实广告点击后的跳转 | 没有可重复的广告点击样本，未执行/未判为通过 |

84 次包含广告 SDK 重试与跟踪请求，不能解释为 84 条广告。两段抓包时长、初始化状态和投放结果不同，因此不计算“拦截率”。无广告卡片出现也不能单独证明过滤成功。

净屏本地近期记录包括 `afd.baidu.com`、`als.baidu.com`、`nsclick.baidu.com`、`appc.baidu.com`、`h2tcbox.baidu.com`、`open.e.kuaishou.com`、`baidu-mipdx.cn.miaozhen.com` 等。基线还观察到腾讯广告、穿山甲等广告 SDK 域名请求。这些域名的阻断依据是内置 anti-AD 列表；没有因名称可疑而直接封锁整个百度主域名或未经验证的新域名。

脱敏机器可读摘要：[summary.json](tieba-tests/2026-11-03/summary.json)。原始 PCAP、贴吧 APK、完整页面截图和测试日志留在本机忽略目录 `.toolchain/tieba-tests/`，不公开上传帖子内容、账号标识或数据包载荷。

## 可以和不能得出的结论

已证实：真实贴吧进程产生的部分广告/跟踪 DNS 请求能够在本地被直接拒绝，公开吧页正常内容在这个测试中仍可加载，不依赖无障碍。

尚未证实：所有贴吧信息流广告消失、同域广告内容被移除、真实广告点击跳转全部被阻止。DNS 无法全局拦截其他应用显式发起的 Activity/Intent；按用户选择，本版也不接管默认链接处理。不会把这类结果写成已通过。

本测试没有小米真机，也未覆盖登录后推荐页、付款/发帖、所有广告投放或所有 MIUI/HyperOS 版本。完整平台覆盖见 [COMPATIBILITY.md](COMPATIBILITY.md)。

## 复现要点

1. 仅在测试模拟器安装官方 APK，停用净屏，记录公开吧页、网络查询和正常内容。
2. 通过系统授权启用净屏，范围选择“仅拦截贴吧”；确认无障碍关闭。
3. 清理测试用贴吧数据并走相同首次同意/拒绝通知/公开页面流程，记录本机拦截计数、近期域名与外发查询。
4. 分别验证正常内容、明确广告卡片和广告点击；没有出现的样本标为未覆盖。
5. 使用 `tools/pcap-dns-summary.py` 只生成 DNS 聚合数据。工具不解析 TCP DNS 重组、TLS 内容或网址载荷，因此不据此声称完成内容级过滤。
